# Baseball Life

DOCX v0.3 기획·구현 명세를 바탕으로 만들고 사용자 요청을 `baseball_balance_v0_4.json`(현재 v0.5.1)에 반영한 고교 야구 육성 시뮬레이션입니다. `design.md`의 네이비·화이트, KBO 서체, 작은 모서리와 기록표 스타일을 적용했습니다.

전체 구현 범위와 버전별 변경 이력은 [history.md](history.md), 대회 일정의 참고 출처와 게임 적용 규칙은 [docs/season-calendar.md](docs/season-calendar.md)에 정리했습니다.

## 실행

```sh
npm install
npm run dev
```

`http://localhost:3000`에서 이름을 입력하고 타자·투수 유형을 선택합니다. 타자는 야구장 위 수비 위치를, 투수는 와인드업·셋포지션·역동적인 투구 실루엣 카드를 눌러 포지션을 고릅니다. 시작하면 학교와 능력치를 무작위로 배정합니다. 시작 전 능력치 미리보기·재추첨·시드 입력은 제공하지 않습니다. 서버 인증과 저장 기능은 없으며 새로고침하면 현재 플레이가 초기화됩니다.

## 플레이

- 훈련 센터: 약한 7·중간 10·강한 13장, 능력별 0~5장을 배분합니다. 회복 훈련을 선택하면 이전 타입과 능력치별 티켓 배분을 보관한 뒤 모든 티켓을 0장으로 만듭니다. 회복은 여러 주가 지나도 유지하며 자동 진행도 계속 회복합니다. 이전 훈련으로 복귀 버튼을 직접 누르면 보관한 타입과 티켓 배분을 복원합니다. 초과 배분을 자동 조정하지 않으며 저장과 진행을 막습니다.
- 훈련 항목은 투수 능력치(구속·제구·변화구), 타자 능력치(컨택·파워·스피드·수비), 공통 피지컬 순서로 구분합니다. 훈련 센터와 훈련 설정 모달에서 투수 항목을 위에 표시합니다.
- 주간 진행: Web Worker에서 날짜순으로 7일을 계산합니다. 요청 ID와 즉시 잠금으로 중복 실행을 막고 성공한 상태만 반영합니다. 실패·시간 초과 시 시작 상태를 유지합니다.
- 자동 진행: 하단의 자동 진행 버튼으로 현재 훈련·성향을 유지하며 계속 진행합니다. 일시정지는 계산 중인 한 주를 완료한 뒤 적용되며, 새 부상·강제 휴식·감독의 역할 제안·커리어 이벤트·드래프트·계산 오류가 발생하면 멈춥니다. 역할 제안은 현재/제안 역할의 능력 점수를 비교하는 모달에서 수락하거나 현재 역할을 유지합니다. 설정을 바꾸려면 먼저 일시정지하세요. 이미 부상 중이라면 다시 자동 진행해 회복 기간을 보낼 수 있습니다.
- 피로 확인: 대시보드 숫자는 야간·휴식 회복 후의 현재 피로입니다. 대시보드에는 회복 후 현재 피로와 지난주 최고치를 요약 표시하며, 훈련 센터에서 다음 주 훈련·회복 예상량을 확인합니다. 훈련 센터는 훈련 발생량과 회복 가능량, 회복 후 예상치를 구분합니다. 스태미나·회복력 50, 경기 없는 정규 훈련 주에 예산을 모두 쓰면 약한 훈련은 +0.95, 중간 +2.3, 강한 +4.115점이 남습니다. 일반 회복은 활동일 0.15·비활동일 0.2점, 회복 훈련은 회복력 50 기준 한 주에 현재 피로의 32%를 줄입니다. 일별 비율은 1−0.68^(1/7)(약 5.36%)이며 회복력 배율을 곱합니다. 한 주 후 피로 100→68, 40→27.2이며 일괄 0으로 만들지 않습니다. 최대 스태미나·회복력에서도 약한 훈련 7장은 피로가 누적되며, 회복 훈련은 회복력에 따라 한 주에 약 25~38%의 피로를 줄입니다. v0.4.2에서 일반 훈련·경기 피로와 자연 회복을 v0.4.1의 1/10로 낮췄으며 회복 훈련의 강한 회복 효과는 유지했습니다. 부상·강제 휴식·비시즌은 실제 훈련량을 줄일 수 있습니다.
- 대시보드: 큰 상단 영역에 선수 프로필(학교·이름·포지션·우투우타·OVR·투타 OVR), 피로, 평판, 팀 정보(이름·전력·시즌 성적)를 모았습니다. 아래는 왼쪽 시즌 기록→일정, 오른쪽 상세 능력치로 배치합니다. 일정 제목 옆에 월을 표시하며 월을 걸치는 주는 두 월을 함께 표시합니다. 상세 능력치의 훈련 설정 버튼으로 모달을 열어 타입·티켓 배분을 변경합니다. 저장하면 훈련 센터와 같은 설정에 반영되며 취소하면 원래 배분을 유지합니다. 훈련 요약·주간 리포트·최근 경기는 대시보드에서 제거했고 성장 그래프는 훈련 센터 맨 아래에 표시합니다.
- 훈련 부상: 피로가 낮아도 실제 훈련일에는 하루 0.05%의 기본 부상 확률이 있습니다. 피로 부상 위험과 독립 결합하며 회복·비시즌·0티켓 훈련에는 기본 확률을 적용하지 않습니다. 새 부상은 자동 진행을 멈춥니다.
- 커리어 이벤트: 감독의 주전 테스트·몸의 이상 신호·스카우트 피드백 3종입니다. 실제 훈련 주에 최소 6주 간격, 조건을 충족하면 주당 25% 확률로 발생합니다. 자동 진행을 멈추고 선택지의 능력치·평판·피로 효과를 보여줍니다. 선택 후 실제 적용량을 확인하며 중복 선택은 막습니다. 이벤트 평판 보너스는 재평가와 진급 후에도 보존합니다.
- 팀 전력: 예상 주전 야수 9명·선발 3명·중간계투 2명·마무리 1명에 가중치 1, 후보에 0.5를 주고 역할 능력을 가중 평균합니다. 타격·수비·투수 전력, 전국 순위, 타 학교 비교와 선수별 가중 점수를 표시합니다. 당일 부상·휴식을 반영하는 출전 명단과 별도로 기본 능력 기준의 예상 주전을 사용합니다.
- 선수·로스터: 100팀·3,000명의 학년·포지션·기본/유효 능력·평판·재능 공개를 확인합니다. 포지션과 관계없이 투수·타자 OVR, 투수·타자·공통 능력치와 출전 자격을 함께 표시합니다. 검색과 정렬을 지원합니다. 역할 전환 후에도 기존 출전 자격을 유지하므로 경기별 투타 겸업이 가능합니다.
- 평판: 현재 주 역할 OVR 60% + 경기 성과 평가 40% + 이벤트 보정을 0~100으로 제한합니다. 출전 전 성과는 중립 50점으로 평가하므로 OVR에 따른 기본 평판이 있습니다. 마지막 성과 평가는 진급·역할 전환 후에도 유지하며 새 경기 기록에 따라 갱신합니다. 훈련이나 이벤트로 OVR이 바뀌면 평판에도 반영합니다. 최종 평판은 성과 백분위 자체가 아니므로 상위 몇 %라는 표시는 사용하지 않습니다.
- 개인 기록: 대시보드와 경기 상세에는 투수·타자 기록을 함께 표시합니다. 상단 탭에서 나의 연도별 타격·투구 기록, 시즌별 필터와 통산 합계를 확인합니다. 대시보드의 연도별 기록 및 드래프트의 상세 기록으로도 열 수 있습니다. 로스터에서 선수를 선택한 뒤 연도별 기록을 누르면 다른 선수의 기록도 열립니다. 시즌이 바뀌면 지난 기록을 보존하고 현재 시즌을 별도 행으로 표시합니다. 통산 타율·OPS·ERA·WHIP는 합산한 실제 기록으로 다시 계산합니다.
- 일정·기록: 전·후반기 주말리그와 이마트배·황금사자기·청룡기·대통령배·봉황대기를 진행합니다. 조별 순위로 참가 팀을 정하고, 전국대회는 부전승·진출·탈락·우승과 라운드별 대진을 반영합니다. 자동 경기 스코어·이닝 기록·나의 경기 기록을 확인합니다. NPC 감독은 경기 일정과 피로에 맞춰 일별 회복을 분산합니다.
- 드래프트: 고3 전체를 대상으로 평판 80%·재능 10%·적합도 10%로 선택합니다. 재능은 1~10을 0~100으로 변환합니다. 적합도는 역할 능력 50% + 구단 포지션 수요 50%이며, 지명 후 수요가 감소합니다. OVR은 평판에 포함되며 별도 가산하거나 OVR로 후보를 제한하지 않습니다. 최종 화면은 고교 커리어와 드래프트 결과 두 패널로 표시합니다. 결과 제목 오른쪽 OVR TOP10 버튼으로 고3 상위 10명의 OVR과 지명 결과를 모달에서 확인합니다. 진급·졸업·신입생 충원을 거쳐 고3 가을 지명일에 종료합니다.

일정은 **2026 실제 개최 기간을 참고한 게임용 편성**입니다. 2027년 이후 공식 확정 일정은 아니며 학교·선수·조 편성·참가 기준·세부 대진은 가상입니다. [일정 출처와 게임 규칙](docs/season-calendar.md)에 참고 자료와 적용 차이를 기록했습니다. 각 시즌 3월 1일 시작, 40주 평일 훈련, 9월 첫 월요일 가상 지명일을 사용합니다. 실제 통계에 맞춘 최종 밸런스가 아닙니다.

## 구조

- `lib/sim/types.ts`: 게임·선수·훈련·달력·경기·보고 데이터
- `lib/sim/engine.ts`: RNG 스트림, 선수 생성, 성장, 피로·부상, 포지션 경쟁, 타석·진루·투수 교체, 기록·평판, 진급·지명
- `lib/sim/worker.ts`: 주간 계산과 오류 응답
- `lib/sim/career-events.ts`: 역할에 맞는 이벤트 선택지와 효과
- `app/components/baseball-life.tsx`: 생성·대시보드·훈련·로스터·일정·결산 UI
- `app/components/player-setup.tsx`, `position-picker.tsx`: 이름·유형·구장 포지션·투수 카드 선택. 원본 PNG를 직접 쓰지 않고 구장은 벡터로 그렸으며 투수 이미지는 새로 생성했습니다.
- `lib/player-creation.ts`: 시작할 때만 새 난수를 받아 학교와 선수 생성. 내부 seed는 자동으로 생성하며 UI에 노출하지 않습니다. 엔진의 결정론 검증 경로는 유지합니다.
- `app/baseball.css`: 반응형 화면 스타일
- `baseball_balance_v0_4.json`: 현재 훈련 피로·회복·드래프트·NPC 계수와 역할 가중치. v0.3 JSON/XLSX는 원본으로 보존하며 현재 엔진과 자동 동기화하지 않습니다.
- `lib/sim/calendar.ts`: 일정 참고 자료, 조별 리그, 대회 참가와 토너먼트 진행
- `lib/team-strength.ts`: 예상 주전·후보 가중 전력과 전국 순위

기본 능력은 소수로 유지하며, 부상 저하·피로·성향을 별도로 적용합니다. 투구 기록은 이닝 소수가 아닌 아웃 수로 저장합니다. 재능은 실제 훈련 경험 10주/30주에 공개합니다. 경기 기록이 없으면 성과 평가는 중립 50점이며 OVR로 기본 평판을 산정합니다. 타율·OPS·ERA는 기록이 없으면 미평가로 표시합니다.

## 검증

```sh
npm run lint
npm run build
npm test
npm run test:balance
```

v0.5.0에서는 74개 테스트와 프로덕션 Worker 동등성 검증을 통과했습니다. OVR이 낮아도 평판 100이면 기존 OVR 제한에 막히지 않고 지명되는 경우, OVR 상승이 평판에 반영되는 경우, 평판·재능·적합도의 80:10:10 합산과 이벤트 보정·진급 유지 등을 검증합니다.

이전 v0.4.7에서 72개 테스트와 프로덕션 Worker 동등성 검증을 통과했습니다. 실제 브라우저에서 이벤트 발생 시 자동 정지, 스피드 +0.5·평판 +1·피로 +1 반영, 회복 주간 피로 41.3→13.1과 이전 훈련 복귀를 확인했습니다.

`npm test`는 결정론·입력 검증·성장 수식·피로 경계·확률·달력·Worker 계산 동등성·부상 복귀·경기 기록 불변식·역할 제안·3시즌 종료를 검사합니다.

v0.4.1 검증에서는 일반 엔진·일정·피로·전력 54개와 드래프트 4개 시나리오를 확인했습니다. 서로 다른 6개 생성 집단의 능력치/지명 Top 10 교집합은 9·10·7·8·9·9명이었고, 실제 3시즌 종료 시나리오에서는 10명이 겹쳤습니다. 이는 개별 검증 결과이며 모든 커리어의 지명 순서가 같다는 뜻은 아닙니다. 이전 v0.4.1 브라우저 검증의 강한 훈련 한 주 피로 43.0·이후 회복 주간 0.0은 이전 계수의 결과입니다. v0.4.2는 피로 누적을 그 1/10로 낮췄습니다.

`npm run test:balance`는 기본 100개 seed를 3시즌 진행하고 `test-results/balance.json`에 OVR, 재능별 성장, 부상일, 기록 분포, 지명/미지명 집단과 주간 계산 시간을 기록합니다. `BALANCE_SEEDS`, `BALANCE_WORKERS` 환경 변수로 실행 규모를 조정할 수 있습니다. 이 시간은 Node Worker 측정값이며 브라우저 성능 측정값은 아닙니다.

**이전 v0.3의 가상 연습경기·피로·드래프트 수식**으로 실행했던 100개 시드의 요약은 [validation/balance-v0.3.json](validation/balance-v0.3.json)에 보관했습니다. 총 13,200주·150,000경기·고3 선수 100,000명을 측정했으며 모든 커리어가 2029년 9월 3일에 종료되었습니다. 8개 Node Worker를 함께 실행한 환경에서 주간 계산 p95는 약 611ms였습니다. 일반 훈련을 유지한 플레이어 집단의 평균 부상일은 0일이므로 높은 피로 방침의 부상 분포는 별도 시나리오로 검증해야 합니다.

`npm run build` 후 `npm start`로 서버를 실행한 상태에서 `npm run test:build`를 사용하면 HTTP 페이지·정적 파일 응답과 **실제 빌드된 Turbopack Worker**의 성공·오류 응답, 순차 엔진과의 동등성을 검사합니다. Playwright로 실제 브라우저에서 선수 생성, 팀 전력, 모바일 가로 넘침, 회복 선택 시 8개 티켓 자동 초기화, 대회 화면을 확인했습니다.
