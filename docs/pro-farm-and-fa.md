# 2군 경기 보장과 FA 조건

## 저장에서 확인한 문제

박해민 2040-11-01 저장의 2040년 2군 일정은 순위 결정전을 포함해 362경기였지만, 349경기가 몰수였고 13경기만 완료됐다. 구단별로는 1~4경기였다. 2군 선발은 구단별 0~3명에 그쳤고 야수 포지션과 불펜도 부족했다. 구단 전체에는 잔류군 투수와 과잉 인원이 남아 있었다.

진짜 선발과 휴식을 요구하는 로테이션에 비해 2군 보충이 없었으며, 계약·방출 판단에서도 1·2군을 함께 운영할 투수 수를 확보하지 않았다. 구단 사정으로 치르지 못한 경기가 낮은 누적 평가와 신고 재영입 실패·방출로 이어질 수 있었다. 당시 72경기 일정의 원본 선수단으로 고정 조건을 재현한 결과, 수정 후에는 1군 인원을 빼오지 않고 2군 정규 360경기 모두 완료, 구단당 72경기를 기록했다.

## 2군 명단과 판정

`lib/sim/pro-farm-roster.ts`는 2군 경기에 **등록 2군+3군 전체**를 전달한다. `lib/sim/pro-farm.ts`는 그 통합 선수단에서 건강한 선발 5명·중간계투 5명·마무리 1명·포수 2명과 각 야수 포지션을 확보한다.

1. 같은 현재 포지션에서 출전 가능한 2군 선수를 먼저 기용하고 3군은 대체·교체·휴식 기회를 받는다. 경기 출전을 위해 3군을 2군으로 강제 등록하지 않는다. 신고선수도 일반 2군 경기 명단에 포함하며 2군 → 3군 → 신고선수 순서로 기용한다. 순환 평가 기회는 상위 군의 정상 출전 가능 여부와 별도로 배정할 수 있다.
2. 남는 NPC 투수는 필요한 투수 보직으로 조정한다. 타자를 투수로 만들거나 사용자 포지션·능력치를 바꾸지 않는다.
3. 통합 선수단 안에서도 채울 수 없는 자리는 무소속 선수나 새 기본 선수로 보강해 3군에 등록한다. 1년 기본 연봉·예산·전체 75명·하위 군 합계 45명 정원을 지킨다. 통합 경기 선수단에 별도의 30명 제한을 걸지 않는다.
4. 정원을 비워야 하면 사용자가 아닌 잉여 인원을 조정하며 기존 보장액은 유지한다. 1군 인원을 빼오지 않는다.

1·2군 필수 인원의 합으로 방출 가능 인원과 미래 예산 예약도 계산한다. 경기 입력 명단은 보강 후 다시 만들어 당일 등록을 반영한다. 경기·기록·능력을 소급 생성하지 않는다.

종료된 구단 2군 일정이 39경기(117경기의 ⅓) 이상인데 절반도 정상 완료되지 않았고 주로 하위 군에 있었던 선수는 `clubGamesShortage`로 보관한다. 해당 시즌은 누적 평가·출전 부족·누적 저평가·잔류 기간 판정에서 제외한다. 신고 재도전 기한도 1시즌 연장하고 원팀에서 다음 해 기본 신고 계약을 협상할 수 있게 한다. 연장은 실제 부족 시즌 수만큼만 저장·검증한다. 정상 일정의 벤치 선수와 1군에서 충분한 기회를 받은 선수는 이 예외가 아니다.

## FA의 실제 조건 차이

`lib/sim/pro-fa-terms.ts`는 현재 포지션·같은 군의 경쟁자·구단 예산·방향·최근 최대 3시즌의 실제 순위와 승률을 사용한다. 예산·정원·보장액 검사는 그대로 적용한다.

| 제안 | 계약과 게임에 반영하는 내용 |
| --- | --- |
| 주전 보장 | 건강한 해당 포지션 선수의 선발 우선권, 일반 강등 보호, 선발 로테이션 우선권 |
| 높은 연봉 | 구단별 연봉 프리미엄, 일반 제안의 기존 상한 유지 |
| 우승 도전 | 최근 실제 성적이 좋은 구단, 상대적으로 조정된 연봉, 주전은 경쟁 |
| 장기 계약/계약 안정 | 평가·나이·예산 범위에서 기간과 연봉을 조정, 1년 제안을 장기라고 표시하지 않음 |
| 리빌딩 핵심 | 구단 재편 방향과 나이에 따른 역할·기간·연봉 |
| 원소속팀 잔류 | 기존 구단과 등록 군을 유지하는 계약 |

최대 3개 제안 중 합법적인 원팀 잔류안을 먼저 포함하고 나머지는 가능한 서로 다른 조건을 고른다. 조회는 소속·계약·다른 선수의 명단을 바꾸지 않는다. 주전 보장·포지션·시작 군은 계약에 저장하며 미래의 같은 포지션 주전 보장을 중복 약속하지 않는다. 신고 신분의 유예 계약을 정식 FA 고액 계약으로 가격 매기지 않는다.

**주전·보직 보장은 실제 계약 의무다.** 1군 보장 선수는 계약 기간에 정규 심사·부상·휴식·필수 인원 보충·저장 재편·포스트시즌·다음 시즌 개막 축소로 2군에 보내지 않는다. 부상·휴식일에는 경기에서 쉬되 1군 등록을 유지한다. 2군 보장은 2군 이상 등록을 유지한다. 야수 선발·선발투수 로테이션·계투 보직에도 우선권을 적용하고, 다른 주포지션으로 바뀌거나 계약이 끝나면 해당 보장은 종료한다. 보장 조건이 저장돼 있는데 잘못 강등된 기존 저장도 등록을 복구한다. 연봉·기간 조건은 실제 급여와 계약 만료 연도에 반영하고 강팀 조건은 실제 최근 성적이 있는 구단에만 제안한다.

## 이적과 포지션

1군 선수는 FA·트레이드 후 1군, 2군 선수는 2군에서 시작한다. 만원인 1군은 합법적인 범위에서 벤치를 2군으로, 만원인 2군은 잉여 벤치를 잔류군으로 조정할 수 있다. 자리를 만들 수 없으면 제안을 만들지 않는다. 수락 시 예산·정원을 다시 확인하고 실제 명단을 바꾼다. 트레이드는 양쪽 배치를 먼저 검증한다. 기록·급여·FA 일수·재직 이력은 보존한다.

포지션 경쟁 목록·기본 주전·등록 심사·계약 경쟁자는 현재 포지션이 기준이다. 현재 3루수라면 3루수와 경쟁한다. 다른 수비 가능 포지션은 부상·휴식으로 해당 포지션 선수가 없을 때 임시 경기 명단을 채우는 용도로만 남긴다. 다른 주포지션의 높은 점수가 건강한 현재 포지션 선수를 밀어내지 않는다. 명시적인 투타 겸업과 고교 배치 방식은 유지한다.

## 신인 확보와 선수단 정리

프로 커리어의 매년 고교 신인 지명은 현재 구단별 주포지션 인원과 1군·통합 2군 필수 인원의 부족분을 확인한다. 부족 포지션을 먼저 지명하고 한 명을 뽑을 때마다 수요를 다시 계산한다. 전년도 성적 역순·전체 90~110명·구단별 9~13명은 유지한다. 합류할 신인을 모두 계약·등록한 뒤 그 인원까지 포함해 잉여 선수를 정리한다. 새 신인을 같은 합류 처리에서 즉시 방출하지 않으며 기존 보장 급여를 보존한다. 기존의 장기 하위 군 체류·출전 부족 등 시즌 종료 판정은 계속 적용한다.

## 요청한 저장 복구

`lib/sim/pro-save-repair.ts`와 `scripts/repair-farm-shortage-save.mjs`는 명시적으로 요청한 경우에만 별도 복구본을 만든다. 실제 몰수·당시 소속·급여·신고 재도전 거절을 확인한 뒤 마지막 방출·은퇴를 보류한다. 과거 경기·선수 능력·급여·수령액·통산 기록은 보존한다. 이전의 유효한 방출 이력은 남기고 마지막 구단에서 유예 계약을 협상하도록 한다. 정원이 넘으면 만료된 하위 군 잉여 계약만 정리한다.

```sh
npm run test:compile
node scripts/repair-farm-shortage-save.mjs INPUT.json OUTPUT.json
```

원본 경로와 같은 출력이나 기존 출력 파일 덮어쓰기는 거절한다. 새 저장의 검증·체크섬·불러오기를 확인한 뒤 출력한다. 통상 불러오기가 은퇴 결정을 자동 취소하지는 않는다.

`tests/pro-farm-market.test.mjs`는 2군 명단·예산·정원·보강, 몰수 시즌의 평가 보류, 현재 포지션 경쟁, 구단별 FA 조건·강팀 근거, 조회 무변경, FA·트레이드의 군 유지, 실제 주전 보장·저장·중복 방지·화면, 명시적인 은퇴 복구를 검증한다.


## 117경기 일정과 포스트시즌

2군은 1군과 같은 날 개막하여 상대별 13경기, 팀당 117경기(리그 585경기)를 치른다. 목요일 휴식이며 올스타 휴식도 유지한다. 13경기는 3연전 4회와 단판 1회로 구성한다. 2군 정규리그 종료 후 상위 4팀이 준결승 3전 2선승, 결승 5전 3선승을 치르고 1군 포스트시즌 전에 마친다. 최대 경기 후 승수가 같으면 정규 순위 우선이다.

엔트리는 2군·3군·신고선수 모두 가능하고 시리즈 시작 시 고정한다. 출전 우선순위는 2군 → 3군 → 신고선수다. 포스트시즌 기록은 정규시즌·1군 포스트시즌과 각각 분리하며 연도별 기록에서 확인할 수 있다. 경기 없는 날과 비시즌에는 평가 출전 기회를 배정하지 않는다.

기존 진행 중 저장은 완료 경기를 유지하고 상대별 미진행 경기를 보충하여 117경기로 재편한다. 늦은 시점의 기존 저장에서는 완료된 기록을 보존하기 위해 종료가 늦어질 수 있으며, 그 경우에도 1군 포스트시즌은 2군 종료 후 시작한다.
