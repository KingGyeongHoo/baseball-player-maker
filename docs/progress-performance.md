# 자동진행 성능 개선

## 2026-11-11: WAR·수비 기록 반영 후 최적화

`14b4327`에서 추가된 WAR 출전평가·수비 기록·이벤트를 유지하면서 주간 계산의 반복 작업을 줄였다.

- 리그 평가 집계에서 해당 연도·군의 기록이 없는 선수는 빈 기록 생성과 합산을 생략한다. 현역 우선 중복 제거와 은퇴 선수 누계는 유지한다. 외부에 반환하는 빈 기록은 매번 새로 만들어 편집이 다른 조회에 영향을 주지 않는다.
- 경기·평가 집계의 고정 기록 항목을 직접 합산해 선수마다 반복 생성하던 키 배열을 제거했다. 수비 기록과 과거 출전 경기 수가 불명확한 기록의 처리도 유지한다.
- NPC 훈련 기본값과 역할별 능력치 가중치 목록을 한 번만 구성한다. 선수에게 주는 훈련 계획은 각각 독립된 객체다.
- 훈련 부하의 피로 가중치를 호출당 한 번씩 읽고 한 순회로 합산한다. 실행 중 매개변수 수정과 휴식 모드를 반영하며 부동소수점 덧셈 순서도 유지한다.

아래 측정 방법으로 변경 전/후를 동일한 ES2022 설정으로 컴파일하고 번갈아 3회 실행한 중앙값이다. 벤치마크 실행 중 다른 테스트·빌드는 실행하지 않았다.

| 시나리오 | 변경 전 | 변경 후 | 계산 시간 감소 |
|---|---:|---:|---:|
| 고교 4주 · 3,000명 | 2,096ms | 1,484ms | 약 29% |
| 프로 4주 · 703명 | 2,425ms | 1,967ms | 약 19% |

각 측정의 최종 상태 JSON에 대한 SHA-256이 변경 전/후 모두 일치했다. 경기·성장·출전평가·WAR·수비 기록·평가 이력·난수 상태와 JSON 속성 순서까지 동일하다. 화면 렌더링·워커 전송·자동 저장 시간은 이 수치에 포함되지 않는다.

관련 회귀 테스트 191개(고교 3시즌 전체 진행 포함), TypeScript 컴파일, 린트, 프로덕션 빌드가 통과했다. 별도로 훈련 계획 간 독립성, 실시간 피로 가중치 변경, 모든 기록 필드·수비 기록 합산, 과거 기록 누락·현역 중복·은퇴 누계를 검증한다.

## 2026-11-10 개선

2026-11-10, main 병합 후 측정·개선.

- 최근 경기 평가 합계를 같은 주의 계산 안에서 재사용한다. 새 경기 기록 추가·교체, 최근 기록 배열 교체, 투타 역할·표본 기준 변경 시 다시 계산한다. 이벤트 중단 후 재개와 외부 편집은 새 캐시로 시작하며 저장 데이터에는 캐시를 넣지 않는다.
- 고교 평가의 학년별 순위는 정렬된 값에서 이진 탐색한다. 같은 값의 공동 순위는 유지한다.
- 자동 평가 보관 시 관찰 입력만 만든다. 고정 상대 시뮬레이션·다년 성과·역할별 상세 평가는 보고서를 열 때 계산한다. 과거 관찰의 입력·평가 ID·복원 결과는 유지한다.
- 성장 둔화 구간 조회에서 항목마다 반복하던 문자열 키 생성을 제거했다. 매개변수는 계속 실시간으로 읽는다.
- 선수 목록을 메모이제이션하고 기록 이동 콜백을 고정했다. 자동진행의 계산 중 표시만 바뀌면 같은 선수 목록을 다시 그리지 않으며, 새 주 결과와 목록 내부 필터 변경은 반영한다.

## 측정

`npm run test:compile` 후 `node scripts/benchmark-progress.mjs --label=current`로 고정 시드의 고교 3,000명·프로 703명 커리어를 각각 4주 진행한다. 선택 이벤트 발생 확률은 측정 프로세스 안에서만 끄고 경기·훈련·등록·평가 계산은 유지한다. 입력 생성·마지막 직렬화 시간은 주간 계산 시간에서 제외한다. `--snapshot`은 최종 상태 비교용 JSON도 만든다.

같은 컴퓨터에서 다른 빌드·테스트를 실행하지 않고 변경 전/후를 번갈아 3회 측정한 중앙값:

| 시나리오 | 변경 전 | 변경 후 | 계산 시간 감소 |
|---|---:|---:|---:|
| 고교 4주 | 2,706ms | 2,222ms | 약 18% |
| 프로 4주 | 2,124ms | 2,008ms | 약 5% |

실제 시간은 일정·저장 크기·CPU 상태에 따라 달라진다. 화면 렌더링·워커 전송·자동 저장 시간을 포함한 체감 속도 전체를 뜻하지 않는다. 변경 전/후의 4주 최종 상태를 구조적으로 비교해 선수·경기·성장·계약·평가 이력·난수 상태가 동일함을 확인했다. JSON 속성 순서는 달라질 수 있다.
